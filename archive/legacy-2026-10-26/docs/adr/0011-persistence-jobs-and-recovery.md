# ADR-0011：持久化任务与恢复草稿生命周期

- 状态：Accepted
- 日期：2026-07-23

## 决策

导入、项目加载/保存、PNG 导出和恢复草稿写入通过单 Worker `JobRunner` 串行执行。
Worker 只接收路径、不可变 copy-on-write 快照、取消令牌和进度回调，不接触活
Document、Widget、QImage 或 QUndoStack。

前台 I/O 使用应用模态进度对话框：Qt 事件循环继续响应，用户可以取消，但项目编辑
暂时禁用。结果回到主线程后校验 document UUID 和 revision；只有匹配的 `.limg`
保存可以建立新的 undo clean index。PNG 导出永不清除 modified。

内容修改停止 60 秒后，将最新快照原子保存到应用数据目录的单一恢复草稿。正式保存
或明确放弃更改会删除草稿。启动时仅专用恢复入口可以解释草稿中的原项目路径；恢复
文档保持 modified 且撤销历史为空。损坏草稿隔离为带时间戳的 `.corrupt` 文件。

## 原因

密集项目压缩、校验和 ICC 转换会持续数秒，不能阻塞 GUI 线程。串行 Worker 限制
并发内存峰值；快照和 revision 校验避免后台结果覆盖后续编辑。恢复文件与正式项目
分离，可在不改变保存语义的前提下降低异常退出损失。

## 后果

- 取消以 Tile 为协作边界，不强制终止线程；
- 自动恢复不会调用 `setClean()`，也不会写入正式项目路径；
- foreground 操作完成前不能编辑，但窗口可重绘、显示进度并响应取消；
- `--smoke-test` 禁用恢复提示，`--io-smoke-test` 独立验证打包后的持久化依赖。
