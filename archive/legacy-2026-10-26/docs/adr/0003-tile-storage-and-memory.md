# ADR-0003：Tile 存储与内存预算

- 状态：Accepted
- 日期：2026-07-23

## 决策

V1 从第一版使用稀疏 `TilePixelStore`。缺失 RGBA Tile 表示全透明；读取返回只读视图；
可写访问先复制当前缓冲区并更新 Tile revision，从而保护已有快照。

P0 同时基准了 256×256 和 512×512，并最终固定使用 **256×256**。选择规则是：
只有当 512 的 4096 全画布遍历至少快 20%，且局部编辑 P95 不比 256 慢超过 10%
时才选择 512。

2026-07-23 的实测中，512 的遍历耗时是 256 的 97.78%，未达到快 20% 的门槛；
512 的平均局部编辑 P95 是 256 的 312.95%，也未通过局部编辑门槛。完整环境和
数值见 [`docs/benchmarks/p0_tile_benchmark.md`](../benchmarks/p0_tile_benchmark.md)。

## 原因

8192×8192 RGBA 单层原始像素约 256 MiB。整层权威数组、QImage 和撤销副本并存会
快速耗尽内存，而 Tile 可以支持稀疏图层、局部重绘和局部撤销。

## 后果

- 所有像素算法必须支持跨 Tile 区域；
- 图层和渲染缓存通过 revision 判断失效；
- V1 的 `tile_size` 固定为 256；
- 改变 Tile 大小属于架构迁移，不能夹带在普通功能提交中。
