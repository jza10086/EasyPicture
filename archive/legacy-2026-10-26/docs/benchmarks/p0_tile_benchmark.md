# P0 Tile、QImage 与内存基准

- 日期：2026-07-23
- 结论：V1 固定使用 **256×256 Tile**
- 原始数据：本地生成于 `build/benchmarks/p0.json`（构建产物，不进入 Git）

## 结果

| 指标 | 256 Tile | 512 Tile |
| --- | ---: | ---: |
| 128×128 局部写入 P95 | 0.211 ms | 0.913 ms |
| 512×512 局部写入 P95 | 0.569 ms | 1.528 ms |
| QImage 转换中位数 | 0.140 ms | 0.491 ms |
| QImage 转换 P95 | 0.183 ms | 0.740 ms |
| 4096 密集层分配 | 69.563 ms | 29.342 ms |
| 4096 密集层遍历 | 59.394 ms | 58.077 ms |
| 8192 密集层分配 | 240.079 ms | 144.970 ms |
| 8192 密集层遍历 | 271.517 ms | 232.155 ms |

实际密集内存：

| 场景 | 权威像素 | 256 Tile RSS 增量 | 512 Tile RSS 增量 |
| --- | ---: | ---: | ---: |
| 4096×4096 RGBA 单层 | 64 MiB | 64.32 MiB | 64.25 MiB |
| 8192×8192 RGBA 单层 | 256 MiB | 256.64 MiB | 257.02 MiB |

Alpha 合成样本的最大通道误差为 1 LSB，满足不超过 1 LSB 的验收要求。256 Tile 的
RGBA → premultiplied QImage 转换 P95 为 0.183 ms，显著低于 5 ms 预算。

## 决策依据

512 Tile 只有在同时满足以下条件时才允许替代默认的 256 Tile：

1. 4096 全画布遍历至少快 20%；
2. 平均局部编辑 P95 不比 256 Tile 慢超过 10%。

本次结果：

- 512/256 遍历耗时比为 0.9778，只快约 2.22%，未通过；
- 512/256 局部编辑耗时比为 3.1295，慢约 212.95%，未通过。

因此选择 256×256。512 的顺序分配和 8192 遍历更快，但不足以抵消画笔、橡皮擦、
局部选区等主要交互路径中的明显劣势。
