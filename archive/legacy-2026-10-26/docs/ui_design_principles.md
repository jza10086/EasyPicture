# UI 输入控件设计原则

本文件记录 EasyPicture 的全局输入控件约定。新增或修改界面时应优先复用现有控件，
避免同一类参数出现不同的操作方式。

## 数值型参数

- 整数数值使用 `DragValueSpinBox`，小数数值使用共享相同内部状态机的
  `DragValueDoubleSpinBox`；两者都不显示右侧增减按钮，不得重新引入
  `QDoubleSpinBox` 的第二套事件状态。
- 空闲时输入框为只读且不可获得文本焦点，只显示水平拖动光标；左键按下阶段不提前
  显示文本插入光标。
- 首次左键释放且未发生拖动后进入文本编辑态，切换为 I 型光标并全选当前内容。
- 进入文本编辑态后，再次点击或拖选时必须像普通文本框一样放置插入点、选择局部内容，
  不得重复强制全选整行。
- 按住左键并移动时进入拖动调整，不进入文本编辑态。拖动开始后隐藏鼠标，并把系统
  指针持续锁定在按下位置，以相对位移调整数值；这样拖动不受屏幕边缘限制。提交或
  撤销时恢复鼠标，并保持在最初按下位置。
- 键盘输入支持数字、`+`、`-`、`*`、`/` 和括号组成的安全表达式，确认时直接
  计算结果。表达式不得调用函数、访问变量或执行代码。
- 普通拖动时，每个屏幕像素默认改变拖动范围的 `1%`；因此不同量级的参数具有一致的
  手感，不再使用固定数值步长。该比例可在“全局设置”中调整。
- 拖动期间按住 `Shift` 时切换为精细模式，每个屏幕像素默认改变拖动范围的 `0.1%`；
  精细灵敏度独立于常规灵敏度，也可在“全局设置”中调整。
- 在拖动过程中按下或松开 `Shift` 必须以当前位置重新建立拖动锚点，不能造成数值跳变。
- 文本输入期间暂时清空蓝色填充；确认并计算完成后才按结果重新绘制填充。
- 文本输入期间左键点击输入框之外会确认结果并退出；按 `Enter` 也会确认，并且必须
  同时吞掉 Enter 的按下与释放，不能触发所属对话框的默认按钮。
- 文本输入或拖动期间，在任意位置按下右键会立即恢复进入本次交互前的数值并退出；
  右键撤销在按下时触发，不等待释放。右键释放及随后的上下文菜单事件也必须被吞掉，
  不能在撤销后弹出菜单。`Esc` 提供相同的撤销行为。
- 蓝色填充表示当前值在默认拖动范围中的比例。
- 最小值、中间值和最大值统一使用同一套渐变、边框、内边距和高度规则，数值变化不得
  改变输入框或填充条的长度与粗细。
- 默认拖动范围与允许手动输入的范围可以不同。例如画笔大小拖动限制在常用范围内，
  但允许手动输入更大的合法值；不透明度等受限参数不得手动越界。
- 新建文档尺寸、图层不透明度、工具参数、选区轮廓粗细以及羽化、扩展、收缩、平滑
  半径、自由变换中心/尺寸/角度和四角坐标均遵守以上规则。

### 数值控件状态与事件所有权

- `DragValueSpinBox` 使用 `QWidget` 外壳和内置 `QLineEdit`，不叠加
  `QSpinBox` 自身的数值编辑状态机。
- 交互状态必须互斥，并通过同一个状态转换入口在 `IDLE`、`WAIT_DRAG`、
  `DRAGGING`、`TEXT_EDITING`、`TEXT_SELECTING` 及 Enter/右键手势清理状态之间
  切换；不得使用多个布尔值表示可能重叠的编辑模式。这对应 Blender 对 Number
  Editing、Text Editing 与 Text Selecting 的显式区分。
- 非文本状态由外壳独占鼠标事件；进入 `TEXT_EDITING` 后，活动会话成为窗口级半模态
  事件所有者，框内的按下、双击、移动和释放统一路由到唯一的 `QLineEdit` 编辑面。
  即使 Qt 把连续点击继续投递给外层浮点包装或旧命中对象，也只能进入
  `TEXT_SELECTING`，不得重新经过 `WAIT_DRAG`。首次进入文本状态只全选一次，
  后续点击与拖选完全遵循普通文本编辑行为。
- 应用级事件路由仅在活动会话期间安装，用于处理框外确认、任意位置右键撤销、
  Enter/Esc/Tab 和窗口失活；同一事件不得再由第二套局部过滤器重复提交。
- `NumericPropertySpec` 统一保存软范围、硬范围、步长、单位后缀和拖动比例。
  鼠标拖动遵守软范围，文本结果遵守硬范围。
- Enter 和右键都按完整手势处理：Enter 的按下与释放均被当前输入会话消费；
  右键撤销后继续消费对应的释放和上下文菜单事件，不使用计时器猜测事件顺序。
- 同一属性同时出现在画布、顶部选项栏或属性面板时，回写必须跳过处于活动交互状态的
  数值控件；用户拖动产生的值不得再以“外部赋值”写回本控件并中断会话。
- 模型到界面的反馈同步必须调用 `syncValue()`；动态范围反馈调用
  `syncPropertyRange()`。这两个接口在控件非 `IDLE` 时返回 `False` 并保留用户会话。
  `setValue()`/`setPropertyRange()` 只用于初始化、文档切换或明确要终止当前交互的
  权威赋值，不得用于 `valueChanged → 模型/Overlay → 属性栏` 的闭环回写。
- 新属性面板接入拖动数值框时，必须增加“控件发出变化后模型立即回写”的回归测试；
  测试至少验证状态仍为 `DRAGGING`、第二次移动继续改变数值、释放时只形成一次提交。
- 数值控件必须明确发送交互开始、成功完成和取消边界。连续拖动期间的所有
  `valueChanged` 属于同一次操作，不能各自生成撤销记录。

### 画布手势的提交边界

- 具有明确画布手势的写操作，以左键释放作为事务确认边界；拖动期间只显示临时预览，
  释放后形成一条文档撤销命令，不再要求第二次点击“应用”。
- 栅格自由变换的移动、缩放和旋转遵守该规则；中心点拖动只是旋转辅助状态，不修改
  像素，因此释放时不提交。数值和键盘变换仍可由 Enter 或“应用”集中确认。
- 图形工具在矩形类手势释放、折线/多边形双击或 Enter 完成时立即创建图形；成功后
  必须保持图形工具和当前输出模式，以允许连续创建。矢量图形创建后选择其父矢量组，
  不能因自动选中新对象而切换到图元编辑状态。
- 拖动期间右键只恢复或取消当前手势，不得提交当前预览。
- 裁切、画布大小、图像/图层缩放、AI 像素整理、精灵切片和 Atlas 导出继续使用各自的
  显式确认流程。颜色调整、像素描边和 Tile 过渡等纯属性试算没有画布释放边界，也继续
  使用显式“应用”或“生成”，避免一次参数探索产生多条破坏性命令。

### 自由变换的会话内撤销

- 自由变换预览维护独立的轻量历史，不提前修改 Document 或文档撤销栈。
- 一次画布拖动、一次数值拖动或文本提交、一次键盘位移分别形成一个会话内撤销点。
- `Ctrl+Z` / `Ctrl+Shift+Z` 在变换会话存在时只操作预览历史；没有可撤销的预览步骤时
  不得穿透到文档撤销栈并破坏当前会话。
- 拖动尚未释放时按下右键，仅恢复本次拖动开始前的变换几何，不取消整个自由变换。
- 画布拖动在左键释放后形成一条文档级原子撤销命令，并立即重建变换手柄以继续操作；
  数值或键盘预览最终按 Enter 或“应用”后仍合并为一条文档级原子撤销命令。
- 顶部选项栏只放宽、高、旋转和模式等高频参数；中心点 X/Y 与四角精确坐标归入右侧
  属性面板。

## 属性右键菜单

- 数值框空闲时和枚举框提供唯一菜单项“设为默认值”，含义是恢复预设值，而不是把当前值保存为新的默认值。鼠标悬停菜单项可查看目标值。
- 数值控件使用 `default_value` / `setDefaultValue()` 声明预设；模型的 `setValue()` / `syncValue()` 回写不得改变预设。没有专门声明时，以构造初值为预设。
- 动态范围内使用当前硬范围钳制预设，但不覆盖原预设；例如过渡宽度默认 8，在 4 像素 Tile 上恢复为 4，回到较大 Tile 后默认仍为 8。
- 恢复动作统一发送一次开始、值变化和完成信号；反馈期间使用 `APPLYING_DEFAULT` 阻止同步回写中断。无变化、禁用或正在编辑时不执行。
- 拖动/文本输入中右键仍只取消该次编辑，并消费其释放与上下文菜单事件；不能把取消手势再解释成默认值菜单。
- 枚举用 `setDefaultValue(item_data)` 声明预设（未声明则为首项），不依赖可能改变的显示下标。普通文字内容输入不添加默认值菜单。
- 自由变换坐标恢复到当前会话初始位置；精灵锚点恢复到当前单格中心。普通预设不写入 `.limg`，恢复后的属性变化仍走原有命令/设置流程。

## 枚举型参数

- 有限且互斥的离散选项使用 `BlenderComboBox` 下拉菜单。
- 下拉框右侧始终绘制向下箭头，不依赖 Windows 或 Qt 当前主题提供箭头。
- 当前值必须直接显示在收起状态；展开列表使用清晰的选中高亮。
- 模式、4/8 邻域等参数不得伪装成数值拖动控件。

## 颜色选择弹窗

- 颜色 Dock 保持紧凑；完整编辑仅在点击前景色或背景色后打开独立弹窗。
- 弹窗默认使用 HSV 圆盘：角度表示色相，半径表示饱和度；右侧独立渐变条表示明度。
  滚轮位于圆盘上时调整明度，`Ctrl` 拖动按 30° 吸附色相。
- RGB、HSV 与 Hex 使用紧凑分段模式切换，一次只显示当前模型的输入字段；Alpha
  始终独立显示。
- 各颜色模型可以互相联动，但同步更新必须跳过 `interaction_state != IDLE` 的数值框，
  不能以程序化 `setValue()` 中断用户正在进行的连续拖动或文本输入。
- 屏幕吸管由当前模态颜色弹窗直接捕获鼠标和键盘；不得再创建无父级全屏透明顶层窗口，
  以免 Windows 的应用模态规则阻断该窗口输入。完成、右键、`Esc`、隐藏和销毁路径都
  必须释放捕获并恢复系统光标。
- 颜色弹窗使用应用自身的深色绘制与中文标签，不依赖平台 `QColorDialog` 的主题、
  本地化或原生控件差异。

## 布尔型与命令型参数

- 布尔状态使用复选框或可切换按钮。
- 会立即执行操作的项目使用按钮或菜单 Action，不使用数值或枚举控件承载命令。

## 图层列表与缩略图

P10E 补充交互约束：

- 计算结果只更新预览与统计，不反向调用数值 `setValue()`；必须反馈时使用 `syncValue()` / `syncPropertyRange()`。
- 点击应用后冻结参数控件直至最新计算提交或取消；取消按钮始终可用。不能提交旧 generation 的结果。
- 调色板单击选中只更新样式，不销毁色块按钮，否则第二次点击无法组成双击。只有颜色集合变化才重建网格。
- 调色板列表可以独立滚动；不要因为 256 个色块增加整个属性 Dock 的最小高度。
- 临时描边不是画布 Overlay，必须在来源层上方的实际组内顺序绘制；展开状态不得随预览或新层生成被重置。
- AI 像素整理的完整结果临时替代来源层显示，不叠加第二份半透明来源。网格和选区范围提示才是 Overlay，不参与导出。
- AI 网格宽高联动与对齐范围同步不得向当前活动字段回写；计算结果只能更新统计、色板和预览。参数非法时按钮与 Enter 应用路径都拒绝提交旧结果。

- 每个图层行显示固定 48×48 的像素缩略图，透明区域使用棋盘格，不把最终画布合成、
  上方图层、图层不透明度或显隐状态烘焙进缩略图。
- 缩略图从权威 straight RGBA Tile 低分辨率采样，只作为 UI 缓存，不得反向写入
  Document。
- 缓存键至少包含像素存储 revision、文档尺寸和图层几何；像素事件只失效对应图层，
  文档尺寸或图层列表变化才清空全部缩略图。
- 缩略图区域不改变既有输入所有权：眼睛区域负责批量显隐，文字区域负责选中、重命名
  和拖动排序，避免拖动缩略图时误改活动图层。
