# ADR-0009：撤销 PatchStore 与内存预算

- 状态：Accepted
- 日期：2026-07-23

## 决策

应用使用一个持久 `QUndoStack`，切换文档时清空并为新文档建立 clean 基线。命令数
上限为 100，撤销负载总预算固定为 **1 GiB**。

像素命令在 `UndoPatchStore` 中保存完整受影响 Tile 的 before/after。数据使用 zlib
level 1；压缩不缩小时保留 raw bytes，并同时记录实际存储量和解压后大小。缺失
Tile 使用零字节句柄，以便撤销后恢复稀疏状态。

删除或撤销后由命令暂存的整层对象按其已分配像素字节计入预算。命令被撤销上限
移除或栈被清空时，句柄必须确定性释放。

推入命令前执行预算判断：

- 单条命令超过 1 GiB 时拒绝，不修改文档；
- 总量将超限时提示用户；
- 取消时保持文档和历史不变；
- 确认时释放旧历史、调用 `resetClean()` 使旧 clean 基线不可达，再执行新命令。

## 原因

QUndoStack 适合 Qt Action、快捷键和 clean 状态，但不提供按字节删除任意最旧命令
的安全接口。P2 采用明确提示后重置全部旧历史，避免构造一个与 QUndoStack 并行的
第二套历史索引。

1 GiB 是用户针对当前本机使用范围选择的上限；100 条数量限制仍独立生效。

## 后果

- 所有 UI 图层和像素变更必须通过 `DocumentCommandService`；
- 无实际变化的请求不得进入栈；
- undo 回到仍有效的 clean index 时文档恢复 clean；
- clean 基线因数量或预算丢失后，文档保持 modified，直到 P3 项目保存成功。
